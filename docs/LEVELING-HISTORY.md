# Leveling history — beta62

Open **General → Leveling history** or `/pr leveling`. Choose a character for the per-level record. Enter any start/end levels and press Compare; 1–max compares the current client's level cap. Account character summaries, fastest qualifying run and class averages (slowest first, sample count shown) use only records with both endpoints. These are Andrew's characters' times, not a controlled class balance benchmark.

Records live in `ProjectRuthlessDB.levelHistory.characters`, keyed by character GUID. Each milestone stores played seconds on reaching that level, an observed Unix timestamp where available, and its source. Name, realm, class, level, cap, last seen and last played-time total are retained. Deleted characters' existing records remain available. WoW's ordinary saved-variable flush on logout/reload persists this data; a process crash can lose unflushed changes.

A single native `RequestTimePlayed()` at login obtains a `TIME_PLAYED_MSG` server baseline. Actual level-up events use a session clock anchored to that baseline, with approximately second-level precision. There is no idle timer, repeated server request or combat-log scan. `/played` includes AFK time; offline time is excluded. Blizzard may print its normal played-time response at login. A manual `/played` refresh also refreshes the baseline.

The current level's entry played-time can be recovered as total played minus time at current level. Its wall-clock timestamp stays unknown because offline periods cannot be reconstructed. Earlier missing milestones are never interpolated. A level-1 origin is known to be zero played seconds, so 1–10 or 1–max may be available from a recovered current-level entry even when individual earlier splits are missing. If the initial server response is delayed, same-session dings wait for that baseline. No baseline means unknown time rather than invented data.

Local harness covers baseline/dings, duplicate events, logout, offline exclusion/reconnect, missing levels, delayed response, class averages, fastest ranges and restricted values.
